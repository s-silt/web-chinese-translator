# Privacy Policy

[简体中文](PRIVACY.md) · English

Applies to the browser extension "Web Chinese Translator". Chrome and Edge provide built-in UI glossaries, model translation, and reading assist; the Firefox version enables local GitHub Chinese localization only and does not run model translation or reading assist. The extension does not run in incognito (private) windows (`incognito: 'not_allowed'`), and incognito windows never record or attach page titles.

## Data Processed

| Data | Content | Storage Location |
| ---------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Page text | Interface text on github.com, gist.github.com, and www.githubstatus.com pages, replaced locally with Chinese | Not stored |
| Page text | Common interface text on 26 preset site groups (see `src/translation/dictionaries/metadata.json` for the full domain list), replaced locally with the target language using built-in dictionaries | Not stored |
| Translation text | Text you select along with nearby visible context, visible text on the current webpage that you manually request to translate or on sites where auto-translate is enabled, and metadata such as the current page title, main heading, and site name; when Smart reading is enabled, candidate paragraphs where you dwell or revisit are also sent to the model endpoint you configured | Selection definitions and Smart reading results are cached only briefly in background memory. Direct page translation and auto-translation results on regular pages are also written in plaintext to local IndexedDB (`web-translator-cache`) and are not synced with your browser account; translated text may contain source text fragments, identifiers, or URLs. Cache keys are computed as SHA-256 digests from the source text, context, endpoint, model, prompt, and other inputs, and those inputs are not stored as separate plaintext fields. Up to approximately 20,000 entries or 20 MB; entries written more than 30 days ago are no longer used for cache hits, with physical deletion triggered by subsequent cleanup; translations on identifiable sensitive pages and requests carrying recent reading clues do not read from or write to persistent storage. |
| Input and document text | Ordinary drafts and supported editor text after the configured typing pause, when input translation is enabled | The current original, translation, and restoration state are held in the webpage's memory; the website may independently save editor content |
| Text translation window | Text you type or paste, sent to your configured model endpoint using the source and target languages selected in the window | Drafts and displayed results are held for the current window; the extension does not write them to settings or persistent translation cache, and does not restore drafts after the window closes |
| Reading clues | Smart reading only: titles of recent pages (up to 160 characters), the first visible main heading (up to 120 characters), site name and timestamp, tab id, and page id; full URLs, browsing history lists, and full page body text are not saved. When Smart reading is enabled, each model request attaches at most 4 recent clues from other tabs and other websites | `storage.session`, accessible only to trusted extension contexts, up to 12 entries, expiring after 30 minutes; cleared when turning off Smart reading, turning off the master switch, revoking site permissions, or modifying the excluded sites list; cleared when the browser session ends |
| Settings | Switches, excluded paths, translation languages, interface language, and appearance | `storage.sync`, which may sync with your browser account; interface language and appearance are also cached in extension page `localStorage` |
| Custom entries | Source text and translations you add | `storage.local` |
| Translation configuration | Model endpoint URL, model name, auto-translate sites, excluded sites (up to 50 domains), built-in UI glossary switches, and custom dictionaries (stored locally only; enabling a dictionary requires access permission for the corresponding website, and entries are used only for local replacement without sending content) | `storage.local` |
| API Key | The model endpoint key you enter | Local IndexedDB (`web-translator-secrets`), not synced with your browser account, stored in plaintext; bound to the endpoint origin (protocol, host, port), requiring re-entry or explicit deletion when changing the origin |
| Custom request headers | Request headers you enter in Advanced settings, which may contain service credentials | Same as API Key: stored in local IndexedDB (`web-translator-secrets`) in plaintext and not synced; bound to the endpoint origin and sent only to the corresponding model endpoint |
| Page marker | The `data-gcn-i-<random id>` attribute on `<html>` during translation, readable by page scripts | Not stored; removed when disabled |

## Retention and Deletion

- To delete your API key, use "Delete key" in Settings. Turning off Smart reading or the extension master switch clears recent reading clues. Clearing regular browsing history or browser cache is not equivalent to performing these deletion actions; how uninstalling the extension or browser cleanup options affect extension data is managed by the browser, and this project has not verified all browser versions and disk-pressure scenarios.
- To clear the persistent translation cache, use "Clear translation cache" in Settings, which empties all translations in local IndexedDB and translation results in background memory, and cancels in-progress translation requests; a notice is shown if clearing fails. Apart from this, deleting the API key, turning off the master switch, modifying excluded sites, or changing the endpoint does not delete existing cache entries. Changing the endpoint or model uses different cache keys; switching back to the same configuration may hit existing entries again if they have not expired. Expired entries are no longer used for translation, but immediate deletion from disk is not guaranteed; scans triggered by subsequent writes clean up entries based on usage time and capacity.
- Modifying the excluded sites list clears existing reading clues; a notice is shown if cleanup fails, and old clues from excluded sites and identifiable high-sensitivity hosts are still filtered out before sending.

## Network Requests

- A saved API Key is sent to your configured endpoint in the `Authorization: Bearer` header during model requests, connection tests, and model list fetches; saved or currently entered custom request headers are also sent with the corresponding requests.
- When disabling the extension, excluding the current page, navigating into an excluded path, changing custom entries, or toggling time localization, if the current page is a Turbo cache snapshot, contains translations written back from GitHub's cache, or has residual old translations (such as after an extension update), the current GitHub page is re-fetched; when Turbo is unavailable, the full page is reloaded.
- When GitHub writes back a translated title or page elements from its own cache (during back/forward navigation, or frame navigation to an anchor URL), if translation has been stopped or those translations are outdated (for example, after changing custom entries, toggling time localization, or updating the extension), the current GitHub page is re-fetched.
- When the extension is updated, uninstalled, or disabled in Chrome or Edge, if the current page is a Turbo cache snapshot or contains translations written back from GitHub's cache, the current GitHub page is re-fetched.
- If any of the above re-fetches is interrupted by frame navigation and old translations remain on the page, it is requested once more.
- Clicking "Reload" in the popup reloads the current page.
- Clicking "Save & connect" or "Test connection" sends a fixed test string to the configured model endpoint to verify that the endpoint and model work, and calculates round-trip latency locally for display; this request contains no webpage content.
- Clicking "Fetch models" sends a `GET /models` request to the currently entered endpoint using the corresponding API Key and custom request headers; no webpage text is sent. The model list is used only for selection, and you can also enter a model name manually.
- When using selection assist, the selected text, a small amount of nearby visible context, and the current page's title, main heading, and site name are POSTed to your configured model endpoint (using OpenAI-compatible `/chat/completions` or `/responses` depending on the selected API type). Manual translation via the context menu sends the selected text and current page metadata. "Translate this page" processes visible translatable text on the current page and applies the same sensitive-content and exclusion rules.
- After selecting Smart reading in Settings, grant website access permissions as prompted by the browser; the interface explains the text, context, and short-lived reading clues that will be used. Candidate paragraphs where you dwell or revisit are sent to the same endpoint; each model request attaches at most 4 recent reading clues. Dwell time, revisit counts, and interaction method are used only for local judgment by the extension and are not sent to the model; the model still knows whether a request was triggered by selection or revisit. Common sensitive paths (such as account, key/credential, payment, and mail pages) and known sensitive hosts (including hash routes and private network addresses) prohibit selection popups, proactive Smart reading, auto-translation, and clue recording; only the explicit context menu can send selected sensitive text, and it does so without attaching the page title, nearby context, or recent clues. This detection is heuristic and is not guaranteed to cover all private pages.
- On domains listed under "Sites excluded from model processing" (which can be added in Settings or via "Exclude this site" in the popup) and their subdomains, all model requests and reading clue recording are prohibited, including manual context-menu translation; built-in UI glossaries continue to work normally.
- After you enable auto-translation for specific sites and grant website access permissions, those sites send visible English text to the same endpoint; per-page character volume has a limit (defaulting to about 50,000 characters, adjustable or settable to Unlimited in Settings), failed segments keep their original text and can be retried manually, and certain errors pause auto-translation on the page. The endpoint may be a third-party service (including compatible relays for models such as Gemini), and any charges are governed by your agreement with that provider; before sending, please confirm that the site's content may be processed by that service.
- After you enable input translation and grant access, eligible drafts are sent to the configured model endpoint after the configured typing pause. Safely writable ordinary inputs and plain document text are replaced directly, without sending messages. Restore uses the exact original temporarily held in local memory without another model request; further editing, changing targets, or closing the panel invalidates that restoration record. Complex formatting offers preview and copy only and is never forcibly rewritten. This temporary extension state is separate from the website's own drafts or autosave. Upgrading from the old manual mode disables input translation until you explicitly enable it again.
- Clicking Translate or using the translation shortcut in the Text translation window sends the text you typed or pasted; it does not automatically attach the current webpage's body, page metadata, or recent reading clues. The window cannot determine which website pasted text came from, so site exclusions and sensitive-page rules are not applied based on that origin. Confirm that the content may be processed by your model service. Opening the window alone does not call a model or change configuration. Copying writes the translation to the system clipboard, whose retention is managed by the operating system. Cancelling or closing the window stops local waiting and attempts to abort the request, but cannot guarantee withdrawal of content already received by the provider.
- Built-in UI glossary matching and replacement do not call a model; GitHub may reload the page when restoring the original text or refreshing translations, under the conditions described above. No other network requests are made beyond those listed above.

## Permissions

- `storage`: Saves settings, custom entries, and translation configuration; `storage.session` stores recent reading clues.
- `scripting`: Registers and injects GitHub dictionary scripts and per-site page scripts.
- Built-in required sites: github.com, gist.github.com, and www.githubstatus.com (GitHub localization) plus 26 preset site groups (built-in UI glossaries; see `src/translation/dictionaries/metadata.json` for the full domain list).
- `activeTab`: Temporarily accesses the current page to inject the translation panel script when you click "Translate this page" or "Translate selected text" in the context menu, or interact with the popup.
- `contextMenus`: Registers the "Translate this page" and "Translate selected text" context menu items.
- `optional_host_permissions`: Model endpoints and auto-translate sites are authorized per origin. Enabling selection assist or input translation requires granting HTTP/HTTPS website access permissions and registers the corresponding page scripts; revoking permissions cancels requests, restores original text, stops the corresponding processing, and clears recent reading clues.
- `alarms`: Cleans up expired reading clues in the background on Chrome and Edge. Clues older than 30 minutes are no longer included in requests; scheduled cleanup may be affected by browser sleep.
- Does not request `tabs` or `history` permissions, and does not read the browser's browsing history list. The Firefox build runs GitHub localization only.

## What We Do Not Do

- Built-in localization features do not send data to the developer or any third party.
- Provider endpoint presets are available to choose from, but no API keys are supplied and no text is sent to a model endpoint while the model is unconfigured; configurations, keys, and page content are never sent back to the extension developer.
- Data is never sold or transferred, and is never used for advertising, creditworthiness evaluation, or any purpose unrelated to translation.
